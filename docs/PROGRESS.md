- Hotfix (outside Stage numbering, 2026-07-29): fixed a critical admin routing/auth bug reported after Stage 23b — `/admin` opened the AdminLayout shell (sidebar/topbar) but main content stayed permanently blank, never resolving to login or dashboard, blocking Stage 23b's own browser verification. Root cause: `frontend/src/admin/router.tsx`'s nested `<Routes>` (rendered as the `element` of the outer `<Route path="/admin/*">`) used ABSOLUTE paths (`"/admin/login"`, `"/admin"`) instead of paths relative to that already-matched prefix — none of them matched, so every request silently fell through to the catch-all (`Navigate to="/admin"`), which itself also failed to match, leaving `<Navigate>` rendering `null` forever with zero visible UI and no console error. Fixed by switching to relative paths (`"login"`, `""`) per React Router's documented descendant-`<Routes>` pattern. While verifying the fix, also found and fixed a second, independent bug in `frontend/src/admin/auth/AuthContext.tsx`: the session-bootstrap effect's `let cancelled = false` flag only suppressed which of React StrictMode's two dev-only effect invocations updated state — it never aborted the discarded invocation's actual HTTP request. Both invocations sent a real `POST /api/auth/refresh` against the same single-use, rotating refresh-token cookie; the backend's atomic single-use claim (`AuthEndpoints.cs`, by design) lets exactly one win and 401s the other, and the kept invocation lost that race consistently — so a freshly-logged-in session was reported as logged-out on every hard reload of a deep link. Fixed with a real `AbortController` so the discarded invocation's request never reaches the server. Both fixes verified via Playwright against isolated throwaway instances (fresh DB, throwaway admin, non-conflicting ports): `/admin` and `/admin/product-attributes` without a session both land on `/admin/login`; login → dashboard → deep link → hard reload all stay authenticated; backend-down shows the login form (not blank); an injected render crash is caught by the pre-existing `AdminErrorBoundary` with a visible retry UI.
